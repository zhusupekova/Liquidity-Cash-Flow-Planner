# Серверный API

## `GET /api/health`

Проверяет состояние сервиса и доступность логической базы `DB`.

## `GET /api/liquidity/summary`

Возвращает сводку операционного дня:

- валюта;
- минимальный лимит;
- прогнозный остаток;
- дефицит;
- количество заявок на согласовании;
- предупреждения;
- статус банковских источников данных.

## `GET /api/requests`

Возвращает реестр заявок и маршруты согласования.

## `GET /api/limits`

Возвращает минимальные лимиты ликвидности по валютам из D1. Если таблицы еще не заполнены, сервер возвращает базовые демонстрационные лимиты.

## `POST /api/requests`

Создает заявку и сохраняет ее в D1. В промышленной версии роль пользователя берется из SSO/серверной сессии. В демонстрационном API роль можно передать заголовком `x-demo-role`.

Разрешенные роли:

- `treasury`;
- `admin`.

Пример тела запроса:

```json
{
  "title": "Крупный клиентский платеж",
  "amountMillions": 120,
  "currency": "KGS"
}
```

## `PATCH /api/requests`

Согласует или отклоняет заявку. Сервер проверяет роль и сохраняет решение в D1.

Разрешенные роли:

- `treasury`;
- `executive`;
- `admin`.

Пример тела запроса:

```json
{
  "id": "FLOW-1788599365191",
  "status": "Согласовано"
}
```

## `PATCH /api/limits`

Изменяет минимальный лимит ликвидности. Сервер разрешает операцию только роли риск-менеджера или администратора.

Разрешенные роли:

- `risk`;
- `admin`.

Пример тела запроса:

```json
{
  "currency": "KGS",
  "reserve": 950
}
```

## `GET /api/audit`

Возвращает последние события серверного журнала аудита из D1. Журнал строится по принципу hash-chain: каждая запись содержит контрольный хэш и ссылку на предыдущий хэш.

## `GET /api/industrial-readiness`

Возвращает список 10 промышленных доработок и их текущий статус.
