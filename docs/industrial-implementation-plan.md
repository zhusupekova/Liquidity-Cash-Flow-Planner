# Промышленный план внедрения

Этот документ отделяет реализованный учебный прототип от промышленной банковской версии.

## Что уже добавлено в проект

- Логическая D1-база данных `DB` в конфигурации публикации.
- SQL-схема и миграция для пользователей, денежных потоков, лимитов, заявок, аудита, интеграций и уведомлений.
- Серверные API-маршруты для проверки состояния, сводки ликвидности, заявок и промышленной готовности.
- Демонстрационная серверная проверка роли при создании заявки.
- Интерфейсная выгрузка отчета в табличный файл и печатный PDF-отчет.

## Что требует доступов банка

1. Тестовый контур АБС.
2. API или файловый шлюз по депозитам, кредитам, корреспондентским счетам и валютным операциям.
3. Политика авторизации банка: Active Directory, LDAP, SSO или внутренний IAM.
4. SMTP/SMS-шлюз или корпоративная система уведомлений.
5. Требования службы информационной безопасности по журналированию, хранению и резервному копированию.
6. Нагрузочный профиль: число пользователей, заявок, счетов, валют, филиалов и частота обновления данных.

## Этапы разработки

1. Согласовать модель данных и роли.
2. Подключить тестовую БД и применить миграции.
3. Реализовать серверные CRUD-операции для заявок, лимитов, источников и аудита.
4. Подключить SSO и перенести ролевые проверки только на сервер.
5. Подключить тестовые источники данных банка.
6. Реализовать маршруты согласования по сумме, валюте, типу операции и уровню риска.
7. Включить неизменяемый аудит с хэш-цепочкой и запретом редактирования событий.
8. Добавить уведомления и эскалации.
9. Утвердить формы отчетов XLSX/PDF.
10. Провести тестирование безопасности, нагрузки и восстановления после сбоя.
